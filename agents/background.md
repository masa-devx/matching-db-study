# 背景と、これまでに決めたこと

このリポジトリを作る前に、別の場所（手元のノート）で考えたことの引き継ぎ。新しい会話は、まずこのファイルを読む。詳しい中身は、下の「参考にするノート」を必要なときに読む（毎回は全部読まない）。

## なぜ作るか

- DB（テーブル設計・JOIN・中間テーブル・インデックス・同時更新）と API の設計、認証と認可を、ミドルのエンジニアとして説明できるレベルにしたい
- まず性能も設計も考えないレガシーコードの形で作り、そのあと測って直すことで、「なぜその設計にしたか」を前と後の事実で説明できるようにする
- 読んだ知識だけでなく、**作って、測って、確かめた事実**として語れるようにする。深く突っ込まれても、なぜ・ほかの方法・弱点・問題が起きたら、まで答えられるようにする
- 題材は、よくあるマッチングアプリ（会員・いいね・マッチ・メッセージ・有料プラン・キャンペーン）。**実務のコード・仕様書・データ・社名・サービス名は持ち込まない**。仕組みだけを、自分の理解で作り直す

## 身につけること（具体的に説明できるようにする12項目）

フロントエンドとバックエンドで試すと理解が深まる、と勧められた項目。どれも「レガシー版で作る → 測る → 直す → もう一度測る」の前と後の数字で説明できるようにする。`explain-step` で解説を作るときは、この表の「説明できるようにすること」を、その一歩の目標にする。

### DB・バックエンド

| 項目 | 主に学ぶ一歩 | 作って測ること | 説明できるようにすること |
| --- | --- | --- | --- |
| テーブル設計 | 01・02・06・07・07b | 表を分ける・つなぐ・あとから増える形にする | なぜその表と列にしたか。分けたのに制約がないと何が入るか（1人にプロフィールが2つ） |
| インデックス | 01b・02・04・06 | UNIQUE・複合・部分インデックスの前と後 | どの SQL のどの条件に効くか。効かない書き方。書き込みが遅くなる代わり |
| JOIN | 03・05・06 | INNER と LEFT・自己結合・NOT EXISTS | 結果の行がどう変わるか。どれを選ぶか |
| トランザクション | 01b・08・09 | 途中で失敗させる・同時に送る | 何をひとまとめにするか。メールなど外へ出すものはコミットのあと。ロックの待ち |
| N+1 | 05・12（一覧は 04 も） | 一覧のクエリの数（1＋N 本） | どこで起きるか（Eloquent の遅延読み込み）。`with()` で何本になるか |
| EXPLAIN | 04 が中心（01b・05・06 でも見る） | `EXPLAIN (ANALYZE, BUFFERS)` の前と後 | Seq Scan と Index Scan。読んだ行・バッファ・時間で比べる |

### フロントエンド（03b から。[docs/frontend.md](../docs/frontend.md)）

| 項目 | 主に学ぶ一歩 | 作って測ること | 説明できるようにすること |
| --- | --- | --- | --- |
| 画面の表示速度 | 04（長い一覧） | Lighthouse の LCP・INP・CLS・`vite build` の大きさ・描き直しの回数 | どこが遅いかの調べ方（ネットワーク・描き直し・バンドル）。直したら何が何ミリ秒になったか |
| API との通信 | 03b・04 | 読み込み中・失敗・`401`・検索の連打 | 呼ぶところを1か所にまとめる理由。古い応答が後から上書きする問題と止め方 |
| 状態管理 | 03b → 05b | Context と Zustand での描き直しの範囲 | どの状態をどこに置くか（サーバーの値・画面だけの値）。Context の限界 |
| コンポーネント設計 | 03b | 1画面1部品のスパゲティコードを、container／presenter に分ける | 分ける基準。props の形。テストしやすさの違い |
| テスト | 03b（改善版） | 直す前に、今の動きを固定するテストを足す | 何を確かめるか（部品・API の呼び出し・状態）。どこまでテストするか |
| 開発効率 | 03b（改善版） | 型・ESLint・Prettier・CI・API がまだないときの仮の応答 | 機械で止めるものと、人が見るものの分け方 |

## 理解を確かめる6つの問い

各一歩で、次の6つに答えられるようにする（解説のページの8章）。

1. なぜそうするのか
2. ほかの方法は？なぜ選ばなかったか
3. 弱点は
4. 問題が起きたら、どう調べて直すか
5. データが10倍・100倍になったら
6. Eloquent でどんな SQL が流れ、どう直したか。Rails（ActiveRecord）・Prisma ならどう書くか

## 進め方の好み

- 返事・解説・コメント・コミットのメッセージは日本語
- 解説は短い文で、表と図を多めに。専門用語は先に1〜2文で説明してから使う
- 一気に作らない。一歩ずつ止まって、理解を確かめてから進む
- 秘密の値のファイル（`.env` など）は読まない
