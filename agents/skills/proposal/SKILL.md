# 人からの提案を相談する

目的：提案を、実務と同じく「価値」と「作り方」の両方から確かめ、決めた理由を残す。

先に [docs/process.md](../../../docs/process.md) の1章（話し合いの決まり）と5-2を読む。

## 1. 聞く

- 提案を、`r-proposal.md` の見出し（困っていること・案・ほかの案・費用と危なさ・やらないとどうなるか）に当てはめる。埋まらない見出しは、人に聞く（問いは3つまで）

## 2. PM の役で聞き返す

- 「だれの何が良くなりますか？」「今やる価値は、今のサイクルの〇〇より高いですか？」「成功を何で測りますか？」
- ロードマップ（`docs/roadmap.md`）のどのエピックに近いかを示す

## 3. リーダーの役で聞き返す

- 「どこを触りますか？」「壊れるとしたら何が？」「Size はどれくらい？」「戻せますか？」
- 弱いところと、代わりの案を必ず1つ出す（そのまま褒めない）。今のコードに関係する所があれば、ファイルと行を示す

## 4. 決めて残す

1. 採る・形を変えて採る・保留（いつ見直すか）・採らない、のどれかを人と決める。役の意見と人の意見が違ってよい。決めるのは人
2. `ticket` で提案のチケットを作り（人が「作る」と言ったら）、「相談の結果」に決めたことと理由を書く
3. 採ったなら、ふつうのチケット（機能・改善・ツールの導入など）を作る案を出し、Status は Inbox にする。仕分けは `pm`

## 終わりの条件

- 提案のチケットに、決めたことと理由がある
