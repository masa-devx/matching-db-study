# スキルの一覧

このフォルダのスキルと、その呼び出し方。Claude Code では `/<名前>` で呼ぶか、「」の言い方で頼む。`.claude/skills` と `.agents/skills` はこのフォルダへのリンクなので、Codex からも使える。

## 一覧

| コマンド | 何をするか | いつ使う | 頼み方の例 |
| --- | --- | --- | --- |
| `/explain-step` | 次の一歩の解説と図を `explanations/<番号>-*.html` に作る。コードは書かない | 新しい一歩に入る前 | 「次の一歩を解説して」「02 を解説して」 |
| `/explain-change` | 書いたコード・SQL・テスト・EXPLAIN の数字を解説し、その一歩のページの「9. 実装の記録」に書く | 一歩の実装が終わったとき | 「実装を解説して」「記録して」 |
| `/study-calendar` | 一歩を 30〜60 分のタスクに分け、確認を取ってから Google カレンダーに入れる | 予定を立てたいとき。explain-step・explain-change の終わりに聞かれたとき | 「カレンダーに入れて」「02 の予定を作って」 |
| `/review` | 差分を、確かめたいこと・開発ルールと照らしてレビューする | 区切りごと | 「レビューして」 |
| `/harness-setup` | 残っている【記入】を数え、質問しながら順番に埋める | セットアップの途中 | 「セットアップを進めて」「技術が決まったので反映して」 |
| `/harness-extend` | スキル・ルール・サブエージェントを型どおりに下書きし、確認を取ってから足す | 新しい手順やルールを足したいとき | 「この手順をスキルにして」「ルールを足したい」 |

## 一歩の流れで使う順番

```text
/study-calendar（予定を入れる）
  → /explain-step（解説を読む）
  → 「実装して」（テストを先に書いて実装）
  → /explain-change（記録を読む）
  → /review（区切りごとに見直す）
```

## スキルを足したとき

1. このフォルダに `<名前>/SKILL.md` を置く（手順は `/harness-extend`）
2. この表と、[../README.md](../README.md) の「作業手順を呼び出す」に1行ずつ足す
