# チケットを実装する

目的：決めた設計とチケットの範囲だけを、レビューできる形の PR にする。設計を変えたくなったら、実装を止めてリーダーの役で相談する。

## 0. 課題を理解したか確かめる

- 今のサイクルの `05-problems.md` に、このチケットの節があるかを見る。なければ、先に `understand-problem` を回す。人が「なぜ起きるか・どう直すか・どう確かめるか」を答えるまで、実装に入らない（2026-11-18 に人が決めた）
- 人が決めた直し方が `03-how.md` と違うときは、`05-problems.md` の「決めたこと」に従う

## 1. 読む

- チケットの本文（`gh issue view <番号>`）・今のサイクルの `03-how.md`・関係する要件（`docs/requirements/`）と `docs/api/`
- AGENTS.md の「作業前に読むルール」の表で、触る領域のルールをすべて読む（`agents/rules/architecture-backend.md` は改訂版の設計。古いコードを触るときは、その10章（移し方）に従う。Larastan の目標はレベル 9（D-016）だが、今の `phpstan.neon` はレベル 6。上げるのは別のチケットにし、足したコードはレベル 9 でも通る書き方にする）
- 秘密の値のファイル（`.env` など）は読まない

## 2. ブランチを切る

- `refactored-repo` を最新にしてから、種類に合うブランチを切る（process.md の2章：`feature/`・`refactor/`・`fix/`・`hotfix/`・`chore/`）
- ボードの Status を In progress にする（`ticket` の「ボードの項目を付ける」）

## 3. テストから書く

- 改善：今の動きを確かめるテストを先に足し、**直す前のコードで通る**ことを確かめる
- 不具合：再現するテストを先に足し、**落ちる**ことを確かめる
- 機能：受け入れの条件ごとのテスト（要件 ID を名前に入れる）
- テストの決まりは `agents/rules/testing.md`。本物の PostgreSQL（テスト用の DB）で流す

## 4. 実装する

- `03-how.md` の「ディレクトリとクラス」の表のとおりに置く。表にないファイルを足すときは、理由を PR の「見てほしいところ」に書く
- チケットにないこと（気づいた別の直し）は足さず、Inbox のチケットの案として報告に挙げる
- コメントは「なぜ」だけを書く

## 5. 確かめる

AGENTS.md の「主要コマンド」で、次を流して結果をそのまま残す。

- テスト（Pest。画面なら Vitest）・Pint・Larastan（画面なら lint・build）
- 測る：流れる SQL の本数（クエリログ）・EXPLAIN・時間。改善なら前と後
- 受け入れの条件を、テストのほかに curl か画面でも1回確かめる

## 6. PR を作る

- コミットの前に止まる（AGENTS.md の「コミットの前に」）。変えたファイルごとに「何を・なぜ」の表と `git diff --stat` を見せ、人が全文の差分を見て OK と言うまで、`git add`（`-N` を除く）・`git commit`・`git push` をしない。レビューの指摘の直し・解説の追記も、同じように止まる
- 本文は `.github/pull_request_template.md` の見出しを埋める（何を・なぜ・ディレクトリとクラス・流れる SQL・テスト・前と後の数字・リリースと戻し方・見てほしいところ）。文は `agents/rules/writing.md` の書き方と言葉で書く
- 文書（`docs/`・`agents/`・`.github/`・AGENTS.md）を触ったら、`python3 -I agents/tools/check-words.py` を流す
- PR の作成も、人の OK のあとに行う。行き先は `refactored-repo`
- PR を作ったらボードの Status を In review にする
- 続けて `code-walkthrough`（解説）と `pr-review`（レビュー）に進むことを伝える

## 終わりの条件

- 人が課題を理解した記録（`05-problems.md`）があり、人が差分を見て OK と言い、PR ができ、テスト・静的検査が通り、測った数字が PR にある

## エラー時

- テストや検査が通らないときは、設定を緩めて通さない。原因と、試したことを伝えて止まる
