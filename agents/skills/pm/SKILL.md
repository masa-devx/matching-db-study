# PM として回す

目的：人と話し合いながら、**なぜ作るか・何を作るか・いつ出すか**を決め、サイクルを前に進める。どう作るかは決めない（`tech-lead` の受け持ち）。

先に [docs/process.md](../../../docs/process.md) の1章（役と話し合いの決まり）と4章（段階）を読む。

## 1. 今どこかを見る

- `docs/cycles/README.md` と、いちばん新しい `docs/cycles/<番号>-<名前>/` のファイルを読み、どの段階まで終わっているかを決める
- ボードを見る：`gh project item-list 9 --owner masa-devx --format json`（Status・種類・Priority）
- 人に「今は〇〇の段階です。次は△△です」と1行で伝え、その段階に進む。言われた段階があれば、そちらを優先する

## 2. 段階ごとの進め方

### 0 仕分け（サイクルの頭）

1. Status が Inbox のチケットを並べ、1つずつ種類・Priority を案として出す（Size はリーダーの役で案を出す）
2. 人と相談して決め、ボードの項目を直す（`ticket` スキルの「ボードの項目を付ける」）。閉じるものは理由をコメントに書く
3. `docs/roadmap.md` を見て、今回のサイクルのエピックと、入れるチケット（5〜8枚）の案を出す
4. 決まったら `docs/cycles/_template/` をコピーして `docs/cycles/<番号>-<名前>/` を作り、`docs/cycles/README.md` に1行足す

### 1 なぜ作るか

1. ビジネス側の役（サポート・運営・営業・マーケのどれか）を名乗り、困りごとを**声と数字で**出す。答え（どう作るか）は言わない
2. 人の質問に、その役として答える。人が聞かないことは言わない（聞くべきことに気づけるかが練習）
3. PM の役に戻り、「だれの・どんな困りごとか」「今どれくらい起きているか」「作らないとどうなるか」を人に1文ずつ言ってもらう
4. `01-why.md` に議事録を書く（届いた声・困りごと・数字・決めたこと・決めなかったこと・宿題）

### 2 何を作るか

1. 範囲の案を人に出してもらい、PM として「今回から外せるものは？」「成功を何で測る？」を聞き返す
2. 受け入れの条件を「〜のとき、〜になる」の形でそろえ、要件 ID を付けて `docs/requirements/<機能>.md` を直す
3. `02-what.md` に書く。終わったら「次はリーダーと、どう作るかです」と伝える（`tech-lead`）

### 10 振り返り

1. `02-what.md` の指標を、リリースのあとの数字と並べる
2. 人に「良かったこと・困ったこと・次に試すこと」を聞き、PM とリーダーの役からも1つずつ出す
3. ハーネス（スキル・役・ルール）で直したいことを拾い、`harness/` のチケットにする案を出す
4. `10-retro.md` と `docs/roadmap.md` の「並び」を直し、次のサイクルの候補を2〜3出す

## 3. 出来事を起こす

サイクルの 5〜8 の段階のどこかで、1サイクルに1回、`incident` スキルで出来事を起こす（2026-11-18 に人が決めた。前は0〜1回）。起こすかどうかと、いつ起こすかは人に言わない。起こしたら `agents/pm-secret.local.md`（git に入らない）に、サイクルの番号と起こした日だけを書く。

## 4. 守ること

- 話し合いの決まり（process.md の1章）：役を名乗る・問いは3つまで・答えを先に言わない・人の案に弱いところと代わりの案を1つ出す
- 議事録は、その場で書く。決まっていないことを決まったように書かない
- チケットを作る・ボードを直す・コメントを書くのは、人が「作る」「直す」と言ったものだけ
- 実務の社名・サービス名・お客さまのデータを持ち込まない

## 終わりの条件

- その段階の「次へ進んでよい条件」（process.md の4章）を満たし、記録のファイルが書けている

## エラー時

- ボードが読めないとき：`project` の権限がないなら、人に `! gh auth refresh -s project` を実行してもらう
