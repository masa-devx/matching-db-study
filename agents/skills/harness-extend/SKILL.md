# スキル・ルール・サブエージェントを足す

ハーネスは作業のたびに読まれるので、足すほど重くなる。足す前に要るかを確かめ、足すときは型どおりにして、目次から辿れるようにする。

## 1. 何を足すかを決める

| 足したいもの | 種類 | 置き場 |
| --- | --- | --- |
| 決まった手順を、毎回同じように進めたい | スキル | `agents/skills/<名前>/SKILL.md` |
| 同じ間違いを繰り返さないようにしたい | ルール | `agents/rules/` |
| 別の文脈で独立に見てほしい・並列に任せたい | サブエージェント | `.claude/agents/<名前>.md` |
| 機械で必ず止めたい（書式・依存の向き・危ないコマンド） | Lint・フック | Lint の設定、`.claude/hooks/` と `.claude/settings.json` |

文章で頼むより機械で止められるものは、ルールではなく Lint・フックを提案する。

## 2. 要るかを確かめる

- **スキル**：同じ手順を2回以上頼んだ、または手順と終わりの条件が決まっている。1回きりの作業はスキルにしない
- **ルール**：agents/README.md の3条件（自明でない・繰り返す・具体的）をすべて満たす。満たさなければ足さず、理由を伝える
- **サブエージェント**：実装の会話から切り離して判断させたい、または並列に作業させたい。既存の8体で足りるなら、頼み方を直すだけにする

先に、既存のもので足りないかを探す（`agents/skills/`・`agents/rules/`・`.claude/agents/` と agents/README.md の目次）。既存のファイルに足せるなら、そちらを提案する。

## 3. 型どおりに下書きする

下書きを見せ、確認を取ってから書く。ファイルを書く前に、同じ名前のものがないか確かめる。

### スキル

- 名前：英小文字の kebab-case。「何をするか」が分かる名前（例：`add-endpoint`・`release-notes`）
- 先頭：`name`（フォルダ名と同じ）と `description`（何をするか＋どんなときに使うか。頼まれ方の例を「」で並べる）
- 本文：目的の1行 → 手順（番号つき。実行するコマンドは AGENTS.md の「主要コマンド」を参照し、書き写さない）→ 終わりの条件 → エラー時
- 確認を取る場面（外に出る操作・取り消せない操作）を、手順の中に書く
- `.claude/skills` と `.agents/skills` は `agents/skills` へのリンクなので、置けば Claude Code と Codex の両方から使える

### ルール

- agents/README.md の「ルールを足す・変える」に従う：まず同じカテゴリの既存ファイルに足す。分けるなら `<カテゴリ>-<内容>.md`
- 1つの領域にしか効かないなら、先頭に `paths:` を付ける（合わない glob にすると読み込まれない）
- 守り方と「なぜ」を1行ずつ。間違いやすい書き方と正しい書き方を、短く並べてよい
- ルールは人が足すかを決める。下書きは「追加案」として見せ、採ると言われたときだけ書く。コミットは、なぜ必要かを添えた専用のコミットにする

### サブエージェント

- 名前：役割が分かる英小文字の kebab-case（例：`api-contract-reviewer`）
- 先頭：`name`・`description`（何をするか。8ステップのどこで使うか）・`model`（判断が重いなら opus、手を動かすなら sonnet）・`tools`（要るものだけ。レビュー役に Edit・Write を渡さない）・必要なら `isolation: worktree`（並列で編集するときだけ。レビュー役には付けない）
- 本文：役割の1文 → 受け取るもの（足りなければ推測せずに確認する）→ 手順 → 報告形式（P0〜P2、報告は日本語）→ 編集するか、コミット・push・PR をしないこと
- 秘密の値のファイルを読まないことを書く

## 4. 目次につなぐ

足したものは、目次から辿れるようにする。

- スキル：agents/README.md の「作業手順を呼び出す」の表と、agents/skills/README.md の一覧に1行ずつ
- ルール：agents/README.md の「ルールの目次」の該当カテゴリに1行。AGENTS.md の「作業前に読むルール」の表にも、読むときが違うなら1行
- サブエージェント：agents/README.md の「サブエージェントの一覧」に1行。8ステップで使うなら agents/prompts/workflow.md の担当の表にも

## 5. 確かめて報告する

- 先頭（frontmatter）の形が正しいか、`name` とファイル名・フォルダ名がそろっているか
- 書いたリンクが切れていないか
- 足したもの・目次に足した行・まだ試していないこと（実際に呼び出して動いたか）を伝える
- コミットは頼まれたときだけ行う

## 雛形へ戻す

2つ以上のアプリで同じものを足したら、雛形（`~/Desktop/personal-development/ai-dev-template/`）へ戻すことを提案する。雛形は、そのリポジトリで直してコミットする。
