# 一歩を分けて、カレンダーに入れる

目的：一歩を 30〜60 分の小さなタスクに分け、迷わず始められる予定にする。

## 1. どの一歩かを決める

- 言われた番号。なければ [explanations/index.html](../../../explanations/index.html) で「未着手」の一番小さい番号を提案して、確認を取る

## 2. タスクに分ける（ざっくりでよい）

- 基本の形（重い一歩は 2・3 をそれぞれ2つに分ける。00・05b は 2・3 を「作る（60分）」1つにする）
  1. 解説を読む・6つの問いを考える（30分）
  2. レガシーコードで作って、問題を測る（60分）
  3. 振る舞いを固定するテストを足して直し、もう一度測る（60分）
  4. 記録を読む・前と後の数字を確かめる（30分）
- 中身は [background.md](../../background.md) の目次と、その一歩のページ（`explanations/<番号>-*.html`。あれば）から取る

## 3. 予定の下書きを出す

- 表で見せる：日時・タイトル・詳細
- タイトル：`DB学習 <番号> <一歩>：<タスク>`（例：`DB学習 02 いいね：レガシーコードで作って測る`）
- 詳細：やること（3〜5行）・開くページ（`explanations/<番号>-*.html`）・終わりの条件
- 日時は聞く。決まっていなければ、カレンダーの空きを調べて候補を出す
- 実務の社名・サービス名・コードは書かない

## 4. 確認を取ってから入れる

- 「入れる」と言われた予定だけ登録する。返事がなければ入れない
- 入れたあと、登録した予定の一覧（日時・タイトル）を伝える

## 終わりの条件

- 確認を取った予定が、カレンダーに入った

## エラー時

- カレンダーにつながらないときは、下書きの表だけ渡して、手で入れてもらう
