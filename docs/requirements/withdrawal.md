# 要件：退会

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-13）。[product.md](../product.md) の「ブロックと退会」。[auth.md](auth.md)・[members.md](members.md)・[blocks.md](blocks.md)
一歩：06（ブロックは [blocks.md](blocks.md)）
目的：[product.md](../product.md) の「ブロックと退会」

このファイルは、会員をやめる・やめた会員をどこにも出さない・同じメールアドレスで登録し直す、を長く表す。レガシー版も改善版も、この要件を守る。要件 ID は `FR-WD-` で始める。画面の要件は [screens.md](screens.md) に `FR-UI-` で書き足す。

## 目的と対象

会員が自分でやめられるようにする。行は消さずに「やめた日時」を残す（論理削除）。やめた会員は、だれからも見えず、ログインもできない。同じメールアドレスで、新しい会員として登録し直せる。

## ユーザーストーリーと優先度

- 会員として、使わなくなったら自分で退会したい
- 会員として、退会した相手が、検索やトークに残らないようにしたい
- 退会した人として、あとで同じメールアドレスで登録し直したい

優先度ごとの範囲：

- 必須（06）
  - 退会する（パスワードを入れ直して確かめる）
  - 退会した会員をどこにも出さない
  - ログインできない
  - もう持っているトークンも使えない
  - 同じメールアドレスで登録し直せる
- 次の段階：退会の理由を聞く・管理者が退会した会員を見る（12）・一定の期間が過ぎたら行を消す（個人情報）
- 対象外：退会の取り消し（元のアカウントに戻す）・休会

## 機能要件と受け入れ条件

退会は、`users` に退会した日時（`deleted_at`）を入れる。いいね・マッチ・ルーム・メッセージ・ブロックの行は残し、読むときに除く。登録し直した会員は、別の会員（別の `id`・`public_id`）で、前のデータは引き継がない。

| ID | 機能要件 |
| --- | --- |
| FR-WD-001 | 退会できる |
| FR-WD-002 | パスワードがちがうと退会できない |
| FR-WD-003 | 退会したらログインできない |
| FR-WD-004 | 退会したら、持っていたトークンも使えない |
| FR-WD-005 | 検索・プロフィールに出ない |
| FR-WD-006 | いいね・マッチ・トークの一覧に出ない |
| FR-WD-007 | 退会した会員には、いいね・ブロックできない |
| FR-WD-008 | 同じメールアドレスで登録し直せる |
| FR-WD-009 | 退会していない会員と同じメールアドレスでは登録できない |
| FR-WD-010 | 登録し直したあと、もう一度退会しても、また登録し直せる |
| FR-WD-011 | ログインしていないと退会できない |
| FR-WD-012 | アカウント停止・強制退会のあいだは、退会できない |

### FR-WD-001 退会できる

- 前提：A はログインしている
- 操作：A がパスワードを入れて退会する
- 期待結果：`204`。A の退会した日時が入る

### FR-WD-002 パスワードがちがうと退会できない

- 前提：なし
- 操作：A がちがうパスワード・空で退会する
- 期待結果：`422`。退会しない

### FR-WD-003 退会したらログインできない

- 前提：A は退会した
- 操作：A が前のメールアドレスとパスワードでログインする
- 期待結果：`401`（メールアドレスかパスワードがちがう、と同じ文。退会したことは言わない）

### FR-WD-004 退会したら、持っていたトークンも使えない

- 前提：A は退会する前にトークンを持っていた
- 操作：そのトークンで、どの API を呼ぶ
- 期待結果：`401`

### FR-WD-005 検索・プロフィールに出ない

- 前提：B は退会した
- 操作：A が検索する・B のプロフィールを開く
- 期待結果：検索に B は出ない（件数にも入らない）。プロフィールは `404`

### FR-WD-006 いいね・マッチ・トークの一覧に出ない

- 前提：A と B はマッチして、メッセージがある。B は退会した
- 操作：A がいいね・マッチ・トークの一覧を見る。B とのルームを開く・送る
- 期待結果：どの一覧にも B は出ない。ルームは `404`。行は残る

### FR-WD-007 退会した会員には、いいね・ブロックできない

- 前提：B は退会した
- 操作：A が B にいいね・ブロックする
- 期待結果：`404`

### FR-WD-008 同じメールアドレスで登録し直せる

- 前提：A（a@example.test）は退会した
- 操作：a@example.test で登録する
- 期待結果
  - `201`
  - 新しい会員（別の `public_id`）になる
  - 前のいいね・マッチ・メッセージは引き継がない

### FR-WD-009 退会していない会員と同じメールアドレスでは登録できない

- 前提：a@example.test の会員がいる（退会していない）
- 操作：a@example.test で登録する
- 期待結果：`422`（FR-AUTH の重複と同じ）

### FR-WD-010 登録し直したあと、もう一度退会しても、また登録し直せる

- 前提：a@example.test で2回退会した
- 操作：a@example.test で登録する
- 期待結果：`201`。退会した行が2つ残っていても登録できる

### FR-WD-011 ログインしていないと退会できない

- 前提：なし
- 操作：トークンなしで退会する
- 期待結果：`401`

### FR-WD-012 アカウント停止・強制退会のあいだは、退会できない

- 補足：2026-11-21 に人が決めた（#257）
- 前提：A は、運営にアカウント停止された（強制退会も同じ）
- 操作：A が、アカウント停止の前にもらったトークンで退会する
- 期待結果
  - `401`「ログインしてください」。退会しない（メールアドレスも書き換えない）
  - 退会してメールアドレスを書き換えると、同じメールアドレスで登録し直して、アカウント停止を抜けられてしまうため
  - やめたいときは、運営に問い合わせる。運営が管理画面で扱う

## 成功基準・非機能要件・制約

- NFR-WD-001：メールアドレスの重なりを、DB の制約で防ぐ（同時に2回登録しても、退会していない会員が2人にならない）
- NFR-WD-002：退会した会員を除いても、検索・一覧の SQL の本数が増えない
- 測るときの試しのデータ：04 の会員 2万人のうち、一部を退会させる（`search00001` のマッチの相手を混ぜる）

## 前提と要確認事項

- 前提
  - 論理削除（`users.deleted_at`）
  - 行は消さない
  - 外部キーの `ON DELETE CASCADE` は、DB で直接消したとき（FR-LIKE-009・FR-MATCH-010・FR-MSG-014）のために残す
- 前提：メールアドレスの UNIQUE は、退会した行を含めると登録し直せない。どう守るか（部分インデックスなど）は、解説の「選択肢」で決める
- 前提：退会した会員を除く条件は、ログイン・トークンを読むところ（今 9か所）・検索・いいね・マッチ・トーク・ブロックのすべてに要る。レガシー版は、コントローラごとに条件をコピーする（コピーし忘れを測る）
- 前提：Firestore 版（05c）には足さない（改善版のときに決める）
- 要確認：なし

## スコープ外

- 退会の取り消し・休会
- 退会した会員の行を、期間が過ぎたら消す
