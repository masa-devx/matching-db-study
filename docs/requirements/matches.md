# 要件：マッチ

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-12）。[product.md](../product.md) の不変条件 6・8。[likes.md](likes.md)
一歩：03（マッチした相手とのメッセージは 05）
目的：[product.md](../product.md) の「マッチ」

このファイルは、マッチを作る・マッチした相手を見る・送った相手にマッチ済みの印を付ける、を長く表す。レガシー版も改善版も、この要件を守る（レガシー版で守れていないものは、改善する段階のテストの対象になる）。要件 ID は `FR-MATCH-` で始める。

## 目的と対象

お互いにいいねした会員どうしをマッチにし、マッチした相手を見られるようにする。05 で「マッチした相手にだけメッセージを送れる」（不変条件 6）の土台になる。

## ユーザーストーリーと優先度

- 会員として、いいねを送り返したその場で、マッチしたと知りたい
- 会員として、マッチした相手の一覧を見たい
- 会員として、自分が送った相手のうち、だれとマッチしたかを見分けたい

| 優先度 | 範囲 |
| --- | --- |
| 必須（03） | いいねを送ったとき、相手からのいいねがあればマッチを作る・送った応答で「マッチしたか」を返す・マッチした相手の一覧・送った一覧に「マッチ済み」の印 |
| 次の段階 | マッチした相手とのメッセージ（05）・一覧に最新のメッセージを付ける（05）・一覧のページ送り（04）・ブロックした相手を出さない（06） |
| 対象外 | マッチの解除・マッチの通知 |

## 機能要件と受け入れ条件

| ID | 機能要件 | 前提 | 操作 | 期待結果 |
| --- | --- | --- | --- | --- |
| FR-MATCH-001 | お互いにいいねするとマッチになる | A が B にいいねを送った | B が A にいいねを送る | `201`。応答の「マッチしたか」が真。A と B のマッチが1つできる |
| FR-MATCH-002 | 片方だけのいいねではマッチにならない | B は A にいいねしていない | A が B にいいねを送る | `201`。応答の「マッチしたか」が偽。マッチはできない |
| FR-MATCH-003 | 1組のマッチは1つだけ | A と B はまだいいねしていない | A と B が、同時にお互いへいいねを送る | マッチはちょうど1つ（0にも2にもならない）。「A と B」と「B と A」を別のマッチにしない |
| FR-MATCH-004 | いいねに失敗したら、マッチもできない | A が B に送り、B も A に送ってマッチした | B がもう一度 A に送る（`409`）・自分あて（`422`）・いない会員あて（`404`） | マッチは増えない |
| FR-MATCH-005 | マッチした相手の一覧を見られる | A が B・C の順にマッチした（A が先に送った相手も、後から送った相手もいる） | A が自分のマッチの一覧を見る | `200`。マッチした新しい順に C・B。相手ごとに、会員の ID・ニックネーム・年齢・プロフィール画像・マッチした日時。どちらが先にいいねしたかに関係なく出る |
| FR-MATCH-006 | 送った一覧に「マッチ済み」の印が付く | A が B・C にいいねを送り、B だけが A に送り返した | A が送った一覧を見る（FR-LIKE-005） | `200`。B は「マッチ済み」が真、C は偽。C も一覧から消えない |
| FR-MATCH-007 | 他人のマッチは見られない（不変条件 8） | A と B にマッチがある | A が B のマッチの一覧を見ようとする | 見られない（「自分の一覧」しか呼べない） |
| FR-MATCH-008 | ログインしていないと使えない | ― | トークンなしでマッチの一覧を見る | `401` |
| FR-MATCH-009 | メールアドレスを確認していないと使えない（不変条件 2） | A がログインしたが、確認していない | マッチの一覧を見る | `403`（FR-AUTH-021） |
| FR-MATCH-010 | 会員が消えたら、その会員のマッチも消える | A と B がマッチした | B を消す（DB で直接。退会は 06） | A のマッチの一覧に B は出ない。A と B のマッチは残らない |

## 成功基準・非機能要件・制約

- NFR-MATCH-001：マッチの一覧・送った一覧（印つき）を見るときの SQL は、件数が増えても本数が増えない（3本以内。N+1 にしない）
- NFR-MATCH-002：自分のマッチを、表を全部読まずに探せる（自分が組のどちら側に入っていても）
- NFR-MATCH-003：いいねを送るときに相手からのいいねを探すのに、表を全部読まない

## 前提と要確認事項

- 前提：マッチは表（`matches`）に持つ。いいねを送ったときに、相手からのいいねがあれば1行入れる
- 前提：レガシー版は、いいねとマッチを別々に書き込む（トランザクションなし）。だれが送るかは 02 と同じく、コントローラの中で JWT を読んで決める
- 前提：03 より前に作られた「お互いのいいね」は、レガシー版ではマッチにしない（開発用のデータだけなので作り直す）。改善版で表を作り直すときに、いいねの自己結合で埋めるかを決める
- 前提：一覧の件数の上限とページ送りは 04 で決める。03 では全部返す
- 要確認：なし

## スコープ外

- マッチの解除（いいねの取り消しも対象外。相手を見えなくするのは 06 のブロック）
- マッチの通知（メール・プッシュ）
- もらったいいねの一覧（07）
