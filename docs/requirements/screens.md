# 要件：画面

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-12）。[frontend.md](../frontend.md)・D-004・D-006・D-014・D-018。画面から呼ぶ API は [api/README.md](../api/README.md)
一歩：03b（会員を探す一覧は 04、メッセージは 05、見た目と動きは 03c、Zustand は 05b）
目的：[product.md](../product.md) の主要な機能を、ブラウザから使えるようにする

このファイルは、画面（`frontend/`）を長く表す。あとの一歩で画面を足すときは、ここに書き足す。レガシー版も改善版も、この要件を守る（レガシー版で守れていないものは、改善する段階のテストの対象になる）。要件 ID は `FR-UI-` で始める。

## 目的と対象

01〜03 で作った API（登録・ログイン・プロフィール・いいね・マッチ）を、ブラウザの画面から使えるようにする。会員を探す一覧はまだないので、相手は URL（`/users/<相手の public_id>`）で開く。URL で会員を指す ID は UUID（`public_id`）で、連番は使わない（D-022。#46）。

## ユーザーストーリーと優先度

- 会員として、画面から登録・ログインしたい
- 会員として、自分のプロフィールを画面で直したい
- 会員として、相手のプロフィールを見て、いいねを送り、マッチしたらその場で知りたい
- 会員として、送ったいいねとマッチした相手を、一覧で見返したい

| 優先度 | 範囲 |
| --- | --- |
| 必須（03b） | ログイン・登録・自分のプロフィール（見る・直す）・相手のプロフィール（いいねのボタン）・送ったいいねの一覧・メッセージ（マッチした相手の一覧）の6画面と、画面の切り替え（React Router）・ログアウト |
| 次の段階 | 会員を探す一覧（04。検索のタブ）・トーク画面（05。メッセージのタブでマッチした相手を押すと開く）・見た目と動き（03c。モーダル・トースト・スケルトン・マッチの演出など。[design.md](../design.md)）・状態を Zustand に移す（05b）・有料会員の表示（07） |
| 対象外 | 画像のアップロード・通知・ダークモードの切り替え・多言語 |

## 画面の一覧

| 画面 | パス | 呼ぶ API | ログインが要るか |
| --- | --- | --- | --- |
| ログイン | `/login` | `POST /api/auth/login` | 要らない |
| 登録 | `/register` | `POST /api/users` | 要らない |
| 自分のプロフィール（ホーム） | `/home` | `GET /api/me`・`GET /api/users/{public_id}`・`PUT /api/users/{public_id}`・`POST /api/auth/logout` | 要る |
| 相手のプロフィール | `/users/:publicId` | `GET /api/users/{public_id}`・`POST /api/me/likes` | 要る |
| 送ったいいね | `/likes` | `GET /api/me/likes` | 要る |
| メッセージ（マッチした相手の一覧） | `/messages` | `GET /api/me/matches` | 要る |
| 検索（04） | `/search` | `GET /api/users`（[search.md](search.md)） | 要る |
| ブロックした相手（06） | `/blocks` | `GET /api/me/blocks`・`DELETE /api/me/blocks/{public_id}`（[blocks.md](blocks.md)） | 要る |

ログインしたあとの画面は、四角の枠の中に、画面（上）とタブ（下）を入れる。上の帯は置かない。

- タブは左から「検索・いいね・メッセージ・ホーム」。検索（`/search`）は 04 で作る（それまでは「準備中」）
- マッチだけの画面は作らない。マッチした相手は、メッセージのタブで見る。05 で、相手を押すとトーク画面に移る（03b のあいだは、相手のプロフィールに移る）
- ログアウトは、ホームのいちばん下に置く
- 枠の幅：スマホ（〜767px）は画面いっぱい、タブレット（768〜1023px）は 600px、PC（1024px〜）は 640px で真ん中に置く。どの幅でも同じ形にする
- ログイン・登録の画面は、真ん中に幅 480px の1列

## 成功基準・非機能要件・制約

- NFR-UI-001：幅 375px（スマホ）から 1280px までで、横にはみ出さず使える
- NFR-UI-002：入力にはラベルがあり、キーボードだけで送れる（`<label>`・`<button>`・Enter で送る）
- NFR-UI-003：API の送り先は1か所で決める（Vite の環境変数 `VITE_API_URL`。既定は `http://127.0.0.1:8000`）
- NFR-UI-004（03c）：OS で「視差効果を減らす」を選んだ人には、動きを止める（`prefers-reduced-motion: reduce`）。出る・消えるだけにする
- NFR-UI-005（03c）：押せる場所は 44×44px 以上。キーボードで動かしたとき、今いる場所に枠が出る（`:focus-visible`）。文字と地のコントラストは 4.5 以上（[design.md](../design.md)）
- NFR-UI-006（03c）：動かすのは `transform` と `opacity` だけ。Lighthouse（スマホ）の CLS を 0.1 以下に保つ。03c の前と後で、LCP・INP・CLS と `vite build` の大きさを測って残す
- NFR-UI-007（03c）：動きと部品のために、新しい依存（ライブラリ・Web フォント）を入れない。ブラウザの標準（`<dialog>`・View Transitions・CSS）と React 19 の標準（`useOptimistic` など）で作る
- 制約：React 19・TypeScript・Vite・React Router。Node は mise の版（26.13.0）。置き場所は `frontend/`。OpenAPI は使わず、型は `docs/api/` に合わせて手で書く（D-006）
- 制約：CSS は、レガシー版はひな形の `index.css`・`App.css` に書く。改善版は部品ごとの CSS Modules と、色・余白・文字の大きさを CSS の変数（カスタムプロパティ）にまとめる

## 前提と要確認事項

- 前提：レガシー版は、ログインの JWT を sessionStorage に置き、`Authorization: Bearer` で送る（D-014）。改善版は HttpOnly の Cookie
- 前提：レガシー版は、1画面に1つの大きな部品で書き、テスト・画面の CI を持たない（D-018）。改善版で Vitest・ESLint・型の検査を CI に入れる
- 前提：API の CORS は、Laravel の標準の設定（`api/*` をどこからでも呼べる）で、Vite の開発サーバー（`http://localhost:5173`）から呼べるかを確かめる。呼べなければ、API の子 Issue で直す
- 前提：メールアドレスの確認のリンクは、今の API（`GET /api/email-verifications/{token}`）をそのまま開く（JSON が出る）。確認の画面は作らない
- 前提：見た目（色・余白・文字・角丸・影・動き）と部品の見た目は、[design.md](../design.md) を正とする（03c で決めた）
- 前提：03c のレガシー版は、見た目と動きだけを足す。失敗・`401`・連打・`422` の扱い（FR-UI-004・013 など）は直さず、改善する段階で直す
- 要確認：FR-UI-028 の「メッセージを送る」で、そのトーク画面に直接移るには、いいねの応答にルームの `public_id` が要る。今の応答にはないので、03c は `/messages` に移る

## スコープ外

- 会員を探す一覧・ページ送り（04）。それまでは、相手を URL で開く
- 有料会員（07）の画面
- 画像のアップロード（プロフィール画像は、シードのデモ画像のパスを選ぶ）
- E2E のテスト（道具は改善する段階で決める）
- ダークモード・Web フォント・音・振動（03c でも入れない）
- 07 のモーダル（有料会員への誘導）の中身。03c で作る確認モーダルの形を使う
