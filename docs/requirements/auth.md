# 要件：認証と認可

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-11）。[product.md](../product.md) の不変条件 1・2・3・8。[decisions.md](../decisions.md) の D-014
一歩：01b（画面での置き場所は 03b）
目的：[product.md](../product.md) の「新規登録」「ログイン」

このファイルは、登録・メールアドレスの確認・ログイン・ログアウト・だれが何をできるかを長く表す。素朴な版も直した版も、この要件を守る（素朴な版で守れていないものは、直す段階のテストの対象になる）。要件 ID は、ほかの要件と区別するため `FR-AUTH-` で始める。

## 目的と対象

会員が自分で登録してログインし、自分のプロフィールだけを編集できるようにする。01 で作ったプロフィールの API に、「ログインした会員だけ」「自分だけ」の決まりを足す。

## ユーザーストーリーと優先度

- 会員として、メールアドレスとパスワードで登録し、ログインして使いたい
- 会員として、自分のプロフィールを、ほかの人に勝手に変えられたくない

| 優先度 | 範囲 |
| --- | --- |
| 必須（01b） | 登録・メールアドレスの確認（と再送）・ログイン・ログアウト・トークンの取り替え・自分の情報を見る・プロフィールの API の認可・ログインの回数制限 |
| 次の段階（03b） | 画面での置き場所（素朴な版は sessionStorage、直した版は Cookie）・CSRF の守りを画面から確かめる |
| 対象外 | パスワードの再設定と変更・メールアドレスの変更・退会（06）・二段階認証・外部のアカウントでのログイン・本人確認の書類 |

## 登録のときに入れるもの

| 項目 | 決まり |
| --- | --- |
| メールアドレス | メールアドレスの形。ほかの会員と同じものは使えない。大文字と小文字は同じものとして扱う（`A@example.test` と `a@example.test` は同じ） |
| パスワード | 8〜64文字（bcrypt は 72バイトより後ろを無視するため、上限を決める）。英数字や記号を混ぜることは求めない |
| 性別 | 性別の表にある値（[members.md](members.md)） |
| 生年月日 | 日付。今日（日本の時間帯）で 18歳以上 |
| 表示名 | 1〜20文字（[members.md](members.md)） |

## トークンと Cookie（直した版）

| もの | 中身 |
| --- | --- |
| アクセストークン | JWT。有効期限 15分。中身は `sub`（会員の ID）・`iat`・`exp`・`jti`（JWT の番号）・`iss`・`aud` だけ。**個人情報や、有料かどうかなどの今の状態は入れない**。署名は HS256、鍵は長い乱数で、秘密の値のファイルで渡す（リポジトリに入れない） |
| 取り替え用のトークン | 不透明な乱数。有効期限 30日。DB には SHA-256 のハッシュだけを保存する。使うたびに新しいものに取り替え、古いものは使えなくする。取り替えでつながったものを「家族」として持つ |
| Cookie | アクセストークンは `access`（`HttpOnly`・`SameSite=Lax`・`Path=/`）、取り替え用のトークンは `refresh`（`HttpOnly`・`SameSite=Lax`・`Path=/api/auth`）。本番では両方に `Secure` を付ける（手元の `http://localhost` では付けない。設定で切り替える） |
| CSRF の守り | `SameSite=Lax` と、状態を変える API（`POST`・`PUT`・`DELETE`）で `Origin` ヘッダーが自分の画面のものかを確かめる |
| CORS | 自分の画面の送り元（手元は `http://localhost:5173`）だけを許し、Cookie を送れるようにする |
| リリースの条件 | 画面と API を同じサイトに置く（別のサイトだと、ブラウザがよそのサイトの Cookie を止めるため） |

## 機能要件と受け入れ条件

### 登録とメールアドレスの確認

| ID | 機能要件 | 前提 | 操作 | 期待結果 |
| --- | --- | --- | --- | --- |
| FR-AUTH-001 | 登録できる | ― | 正しい5項目を送る | `201`。会員とプロフィールができる。確認のメールが Mailpit に届く。この時点では確認済みでない |
| FR-AUTH-002 | 18歳未満は登録できない | 今日が 2026-11-11（日本の時間帯） | 生年月日 2008-11-12（17歳）・2008-11-11（18歳）を送る | 17歳は `422` で登録しない。18歳は登録する |
| FR-AUTH-003 | 同じメールアドレスでは登録できない | `a@example.test` の会員がいる | `A@example.test` で登録する | `422`。登録しない（同時に2つ送られても、DB が片方を断る） |
| FR-AUTH-004 | パスワードは 8〜64文字 | ― | 7文字・65文字で登録する | `422`。登録しない（8文字・64文字は登録する） |
| FR-AUTH-005 | 確認のリンクで、メールアドレスを確認できる | 登録した直後 | メールのリンクを開く | 確認済みになる |
| FR-AUTH-006 | 確認のリンクは 60分で切れ、1回しか使えない | ― | 61分後に開く・2回開く | 確認済みにならない（`403`）。2回目は「確認済み」を返すだけで、何も変えない |
| FR-AUTH-007 | 確認のメールをもう一度送れる | ログインしていて、まだ確認していない | 再送を頼む | 新しい確認のメールが届く。同じ会員から 1分に1回まで（`429`） |

### ログイン・取り替え・ログアウト

| ID | 機能要件 | 前提 | 操作 | 期待結果 |
| --- | --- | --- | --- | --- |
| FR-AUTH-010 | ログインできる | 会員がいる | 正しいメールアドレスとパスワードを送る | `200`。直した版は `access` と `refresh` の Cookie が付く（JSON にトークンは入れない） |
| FR-AUTH-011 | 失敗のときは、どちらが違うかを教えない | ― | ないメールアドレス・違うパスワードで送る | どちらも `401`。言葉も同じ（「メールアドレスかパスワードが違います」） |
| FR-AUTH-012 | ログインを何回でも試せない | ― | 同じメールアドレスと IP で、1分に6回失敗する | 6回目は `429` |
| FR-AUTH-013 | アクセストークンは 15分で切れる | ログインした | 16分後に API を呼ぶ | `401` |
| FR-AUTH-014 | 取り替え用のトークンで、新しいアクセストークンをもらえる | ログインした | 取り替えを頼む | `200`。新しい `access` と `refresh` の Cookie。古い `refresh` はもう使えない |
| FR-AUTH-015 | 使ったあとの取り替え用のトークンが、もう一度使われたら止める | 取り替えをした | 古い `refresh` でもう一度取り替えを頼む | `401`。その家族の取り替え用のトークンを全部使えなくする（盗まれたと考える） |
| FR-AUTH-016 | ログアウトできる | ログインした | ログアウトする | `204`。その端末の取り替え用のトークンを使えなくし、Cookie を消す |
| FR-AUTH-017 | 自分の情報を見られる | ログインした | 自分の情報を見る | `200`。会員の ID・メールアドレス・確認済みかどうか |

### だれが何をできるか（認可）

| ID | 機能要件 | 前提 | 操作 | 期待結果 |
| --- | --- | --- | --- | --- |
| FR-AUTH-020 | ログインしていないと、プロフィールは見られない | ― | トークンなしで 01 のプロフィールを見る | `401` |
| FR-AUTH-021 | メールアドレスを確認していないと、機能を使えない（不変条件 2） | ログインしたが、まだ確認していない | プロフィールを見る・編集する | `403`。自分の情報を見る・確認のメールの再送・ログアウトはできる |
| FR-AUTH-022 | 自分のプロフィールだけを編集できる | 会員 A がログインした | 会員 B のプロフィールを編集する | `403`。B は変わらない |
| FR-AUTH-023 | 「自分」はトークンで決める | 会員 A がログインした | 自分のプロフィールを編集する | URL の ID ではなく、JWT の `sub` で本人かを確かめる |

## 素朴な版と直した版

素朴な版は、Laravel 5 系のころによくあった形で作る。次の表の「素朴な版」の列は、直す段階で上の要件を守れるようにする。

| | 素朴な版（legacy-repo） | 直した版（refactored-repo） |
| --- | --- | --- |
| ログインの応答 | JSON で JWT を返す（`{"token": "..."}`）。有効期限は 30日。止める仕組みなし | `access`（15分）と `refresh`（30日）を HttpOnly の Cookie で渡す |
| 取り替え・ログアウト | 取り替えなし。ログアウトは「画面で消すだけ」（サーバーは何もしない） | 取り替え用のトークンを DB で持ち、取り替え・使い回しの検知・ログアウトで止める |
| JWT の中身 | 会員の情報（メールアドレス・有料かどうか）も入れる | `sub` などだけ |
| ログインの回数 | 何回でも | 1分に5回まで |
| 確認のリンク | 確認用の文字を `users` の列に入れ、有効期限なし | 署名つきのリンク（Laravel の標準）で 60分 |
| プロフィールの API | URL の ID のまま（だれでも、だれのものでも） | JWT の `sub` の本人だけ |
| パスワード | どちらも bcrypt のハッシュ | 同じ |

## 成功基準・非機能要件・制約

- NFR-AUTH-001：アクセストークンの確かめに DB を使わない（署名と期限だけで確かめる）。取り替えのときだけ DB を見る
- NFR-AUTH-002：ログインの失敗のときも、成功のときとほぼ同じ時間で返す（パスワードの照合を飛ばさない）。ないメールアドレスのときも、決まったハッシュで照合して時間をそろえる
- JWT の鍵は、秘密の値のファイルで渡す。AI は秘密の値のファイルを読まない・書かない
