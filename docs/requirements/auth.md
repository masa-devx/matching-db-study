# 要件：認証と認可

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-11）。[product.md](../product.md) の不変条件 1・2・3・8。[decisions.md](../decisions.md) の D-014（2026-11-20 に D-027 で置き換え：セッションにした）
一歩：01b（画面での置き場所は 03b）
目的：[product.md](../product.md) の「新規登録」「ログイン」

このファイルは、登録・メールアドレスの確認・ログイン・ログアウト・だれが何をできるかを長く表す。レガシー版も改善版も、この要件を守る（レガシー版で守れていないものは、改善する段階のテストの対象になる）。要件 ID は、ほかの要件と区別するため `FR-AUTH-` で始める。

## 目的と対象

会員が自分で登録してログインし、自分のプロフィールだけを編集できるようにする。01 で作ったプロフィールの API に、「ログインした会員だけ」「自分だけ」の決まりを足す。

## ユーザーストーリーと優先度

- 会員として、メールアドレスとパスワードで登録し、ログインして使いたい
- 会員として、自分のプロフィールを、ほかの人に勝手に変えられたくない

| 優先度 | 範囲 |
| --- | --- |
| 必須（01b） | 登録・メールアドレスの確認（と再送）・ログイン・ログアウト・自分の情報を見る・プロフィールの API の認可・ログインの回数制限 |
| 次の段階（03b） | 画面での置き場所（レガシー版は sessionStorage、改善版は Cookie）・CSRF の守りを画面から確かめる |
| 対象外 | メールアドレスの変更・退会（06）・二段階認証・外部のアカウントでのログイン・本人確認の書類 |

## 登録のときに入れるもの

| 項目 | 決まり |
| --- | --- |
| メールアドレス | メールアドレスの形。ほかの会員と同じものは使えない。大文字と小文字は同じものとして扱う（`A@example.test` と `a@example.test` は同じ） |
| パスワード | 8〜64文字、かつ 72バイトまで（bcrypt は 72バイトより後ろを無視するため。日本語は1文字が3バイトなので、文字の数だけでは止められない）。画面では文字の数で伝える。英数字や記号を混ぜることは求めない |
| 性別 | 性別の表にある値（[members.md](members.md)） |
| 生年月日 | 日付。今日（日本の時間帯）で 18歳以上 |
| 表示名 | 1〜20文字（[members.md](members.md)） |

## セッションと Cookie（改善版。D-027）

| もの | 中身 |
| --- | --- |
| セッション | Laravel Sanctum の SPA 認証（Laravel の標準のセッション）。ログインした会員を、サーバーの表 `sessions` に覚える。ブラウザには、セッションの番号だけを Cookie で渡す。ログインのたびに、番号を作り直す |
| 切れる時間 | 操作がないまま24時間（`SESSION_LIFETIME=1440`）。リクエストのたびに、期限が24時間先に延びる。「ログインしたままにする」（`remember_token`）は使わない |
| Cookie | セッションの Cookie（`HttpOnly`・`SameSite=Lax`・`Path=/`）。本番では `Secure` を付ける（手元の `http://localhost` では付けない。設定で切り替える）。ほかに、CSRF のトークンの Cookie `XSRF-TOKEN`（画面から読める。わざと） |
| CSRF の守り | `SameSite=Lax` と、Sanctum の CSRF のトークン。書き込み（`POST`・`PUT`・`PATCH`・`DELETE`）は、ヘッダー `X-XSRF-TOKEN` がセッションのものと違えば `419`。`GET` で書き込まない |
| CORS | 自分の画面の送り元（手元は `http://localhost:5173`）だけを許し、Cookie を送れるようにする |
| リリースの条件 | 画面と API を同じサイトに置く（別のサイトだと、ブラウザがよそのサイトの Cookie を止めるため） |

## レガシー版と改善版

レガシー版は、Laravel 5 系のころによくあった形で作る。次の表の「レガシー版」の列は、改善する段階で上の要件を守れるようにする。

| | レガシー版（legacy-repo） | 改善版（refactored-repo） |
| --- | --- | --- |
| ログインの応答 | JSON で JWT を返す（`{"token": "..."}`）。有効期限は 30日。止める仕組みなし | セッションの Cookie（HttpOnly）。JSON にトークンは入れない |
| ログアウト | ログアウトは「画面で消すだけ」（サーバーは何もしない） | セッションの行を消す。同じ Cookie は `401` |
| 切れる時間 | 30日（使っても延びない） | 操作がないまま24時間（使うたびに延びる） |
| ログインの回数 | 何回でも | 1分に5回まで |
| 確認のリンク | 確認用の文字を `users` の列に入れ、有効期限なし | 署名つきのリンク（Laravel の標準）で 60分 |
| プロフィールの API | URL の ID のまま（だれでも、だれのものでも） | ログインしているセッションの本人だけ |
| パスワード | どちらも bcrypt のハッシュ | 同じ |

## 成功基準・非機能要件・制約

- NFR-AUTH-001：毎回のリクエストで、セッション（表 `sessions`）と会員の状態（退会・停止・強制退会）を DB で確かめる。止めた会員は、次のリクエストから使えない（2026-11-20 に、JWT の「DB を使わない」から変えた）
- NFR-AUTH-002：ログインの失敗のときも、成功のときとほぼ同じ時間で返す（パスワードの照合を飛ばさない）。ないメールアドレスのときも、決まったハッシュで照合して時間をそろえる
- セッションの Cookie の暗号の鍵（`APP_KEY`）は、秘密の値のファイルで渡す。AI は秘密の値のファイルを読まない・書かない
