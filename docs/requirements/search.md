# 要件：検索と一覧

状態：確定
元資料：ユーザーとの会話で決めたこと（2026-11-12）。[product.md](../product.md) の「検索と一覧」・不変条件 2・7。[members.md](members.md)・[likes.md](likes.md)・[screens.md](screens.md)
一歩：04（ブロックした・された相手を除くのは 06、有料会員の表示は 07）
目的：[product.md](../product.md) の「検索と一覧」

このファイルは、会員を探す・一覧で見る、を長く表す。レガシー版も改善版も、この要件を守る（レガシー版で守れていないものは、改善する段階のテストの対象になる）。要件 ID は `FR-SEARCH-` で始める。画面の要件は [screens.md](screens.md) に `FR-UI-` で書き足す。

## 目的と対象

会員が、相手のプロフィールの項目（性別・年齢の幅・都道府県・身長）で絞り込み、最近ログインした相手から順に見て、いいねを送る相手を見つけられるようにする。03b までは、相手を URL（`/users/5`）で開くしかなかった。

会員は 2万人を目安にする。速さの目標は置かず、実行計画・SQL の本数・かかった時間・画面の表示速度は、記録だけする（改善する段階で、前と後を比べるため）。

## ユーザーストーリーと優先度

- 会員として、条件を選んで相手を探し、気になった人のプロフィールを開きたい
- 会員として、もういいねした相手や、まだ使い始めていない会員は、探すときに見たくない
- 会員として、一覧を下まで見たら、続きが自然に出てきてほしい

| 優先度 | 範囲 |
| --- | --- |
| 必須（04） | 検索の API（絞り込み・並び・続き）・最終ログインを残す・検索の画面（検索のタブ・2列のカード・絞り込み・下までスクロールで続き）・2万人の試しのデータ |
| 次の段階 | ブロックした・された相手を除く（06）・有料会員の印（07） |
| 対象外 | 並び方を選ぶ・条件を保存する・キーワードで探す・おすすめの順 |

## 成功基準・非機能要件・制約

- NFR-SEARCH-001：1回の検索で流れる SQL は、件数が増えても本数が増えない（3本以内）
- 速さ（API の時間・実行計画・Lighthouse の LCP と CLS）は、目標を置かない。会員 2万人で、1ページ目と深い続き（5,000件目のあたり）を測って、記録だけする
- 制約：試しの会員 2万人は、シーダーで作る（`users`・`profiles`。性別・生年月日・都道府県・身長はばらつかせる）。開発用の DB にだけ入れ、テスト用の DB には入れない

## 前提と要確認事項

- 前提：最終ログインは、`users` に時刻の列を足して、ログインのたびに書き換える
- 前提：年齢は、生年月日から、その日の時点で数える（誕生日の前なら1つ少ない）
- 前提：レガシー版は、続きを OFFSET（`?page=2`）で読み、改善版で「最後に見た会員の最終ログインと ID」から続ける形（カーソル）に直して比べる。FR-SEARCH-008 はレガシー版では守れない見込み
- 前提：レガシー版の生年月日・身長は文字の列（01 のまま）。文字で比べる問題も、レガシー版で測る
- 要確認：なし
