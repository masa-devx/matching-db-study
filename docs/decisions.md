| D-012 | 有効 | 01 | 性別と都道府県は、マスタの表（`genders`・`prefectures`）と外部キーで持つ。性別の値は 男性・女性・その他・回答しない | 小さな数＋CHECK・PostgreSQL の ENUM 型・自由な文字 | 性別は男性・女性以外も考えられ、値が増える見込みがある。行を足すだけで増やせ、名前と並び順も DB に持てる。外部キーで、表にない値は入らない。都道府県も同じ形にそろえ、範囲を書かずに守る | 改善したあとに足す（[01](../explanations/01-members.html)） |
| D-013 | 有効 | 01 | 身長は、DB では型（`smallint`）だけを守り、範囲（120〜220）はバックエンドのバリデーションで守る | DB の CHECK でも範囲を守る | ありえない身長が入っても、表示が変になるだけで、ほかのデータや検索は壊れない（database.md の「画面を通らない書き込みでも壊れてはいけないか」が No）。型は守らないと、数で比べる・並べることができなくなるので DB で守る | 改善したあとに足す（[01](../explanations/01-members.html)） |
| D-014 | 有効 | 01b・03b | 認証は JWT。レガシー版は、ログインの応答（JSON）で有効期限の長い JWT を返し、止める仕組みを持たない。03b の画面は sessionStorage に置く。改善版は、JWT（15分）と取り替え用のトークン（30日。DB にハッシュで保存・取り替えのたびに作り直す・使い回しを見つけたら家族ごと止める）を、どちらも HttpOnly の Cookie に置く。Cookie は `HttpOnly`・`SameSite=Lax`、本番だけ `Secure`。BFF は作らず、画面から API を直接呼ぶ。リリースするときは、画面と API を同じサイトに置く | Sanctum の SPA 認証（セッション）・Sanctum の API トークン・BFF（画面専用のサーバーがトークンを預かる）・トークンを localStorage に置く | JWT の形（だれでも読める中身・止められない期限・取り替え用のトークン）を、レガシー版の失敗から学ぶ。HttpOnly の Cookie にすると、XSS があってもトークンを持ち出されにくい。取り替え用のトークンの表で、DB の設計（ハッシュ・期限・家族）も学べる。画面と API が別のサイトだと、ブラウザがよそのサイトの Cookie を止めるので、同じサイトに置くことを条件にする | 改善したあとに足す（[認証とトークンの絵本](https://claude.ai/artifact/EW5HWFdTJgLd3JYewyP4bE)） |
